# Hana Coder

四组开发者卡片，统一使用 Hana 组件和原生暗调插画：

1. **Issue**：分组确认、修复汇报。
2. **PR**：列表、详情、来源、简介与按提交版本审阅。
3. **工作树**：分支与目录状态、用途简介、半自动刷新。
4. **命令面板**：单行命令、独立播放按钮、自然语言添加。

## 使用

通过 Hana 的配方管理安装本目录或 `.recipe` 归档。安装后直接对 Agent 说：

- 「看看这个仓库有哪些工作树。」
- 「把最近七天的 Issue 整理一下。」
- 「看看待审 PR。」
- 「审阅 PR #42，重点看看附件兼容。」
- 「给这个项目做个常用命令面板。」

Agent 自动选择模板、读取真实数据并生成卡片，无需用户记模板名。单说「打开 Hana Coder」默认显示当前仓库的工作树。

## 环境

本地状态需要 Git 与 Python 3。GitHub 数据需要已登录且有读取权限的 GitHub CLI（gh）。卡片刷新、提交和执行需 Hana 宿主能力及授权；独立浏览器只能看快照，不能凭导出的卡片获得仓库操作权限。

源模板中的示例数据仅用于离线展示；实际调用必须先采集目标仓库，不将示例当真实结果。

## 开发验证

使用 Node.js 24.15.0（或兼容的 Node 24）、Python 3 和 Git：

```sh
npm ci --ignore-scripts
npm test
```

GitHub Actions 运行相同检查。普通使用不需要安装这些开发依赖。

公开配方 ID 为 `hana-coder`。内部事件保留 `hana-corder.*` 命名空间，以保持既有事件处理契约；它不是另一个安装依赖。

## 文件

- `SKILL.md`：入口路由、卡片选择与总体规则。
- `references/`：摘要、审阅、Issue 协作、命令和事件回写规范。
- `assets/`：五个 HTML 模板、共享组件 CSS、四张 Hero。
- `scripts/`：只读采集与绑定明确仓库的卡片准备脚本。
- `tests/`：定向行为验证。

模板含精简提交指令，配方含完整操作规程。用户批注不会自动成为外部写入授权；审阅不会自动发 GitHub review，刷新不会自动合并或修改代码。
