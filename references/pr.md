# PR：获取、摘要、审阅与批注

## A. 列表与来源

列表用 prepare.py prs；指定编号用 --number。先读取真实事实再铸卡，不在卡片出现后让用户补完初始化。GitHub 读取采用 gh 已有认证，不把 token 写进卡片、配方或 URL。

必须保留 PR 原链接、host/owner/repo#number、base/head SHA、fork 来源。检查详情只链接到真实 API 返回的 CI URL。未知 mergeable 不解释成无冲突；空检查列表不解释成全部通过。达到列表上限要显示查询范围，不能说“所有 PR”。

CI 是仓库流程实际运行的结果。GitHub reviewDecision 是远端评审状态。Agent review 是本地分析结果，三者不可互相覆盖。

## B. 简介：轻量但有依据

普通刷新只阅读标题、描述和已取得的文件信息，必要时针对性补查。简介写目的和范围，通常一句话。摘要与关注点不表示已审阅 diff；描述不足时标明缺口。

`hana-corder.enrich-prs` 提示词应包含：

> 读取来源卡片 state.model，核对 refreshId、仓库和 PR 身份。事实已经更新。按描述和现有文件信息为各 PR 写一句简介及必要关注点；普通刷新不启动完整审阅。向同一 cardEntityId 回写 pr-enrich，成功或失败都完成本次请求。不要发布 review、评论、push 或 merge。

结果按 PR id 关联，不用列表位置或分支名作为键。

## C. 点击「审阅」

这不是 GitHub approve。用户批注是本轮关注方向，不是外部写入授权，也不能替代仓库规范。

### 审阅步骤

1. **确认目标**：精确来源卡片、reviewId、PR id、head SHA、base SHA 和批注。记录开始时目标；不要从全局焦点推断。
2. **理解意图**：读取描述、相关 Issue 和已有讨论，识别期望行为与本次范围。
3. **检查真实改动**：获取该版本 diff，读必要的前后文、调用者、类型和测试。大型 diff 分文件读取；未读完要说明，不能将截断内容当作完整审阅。
4. **核实发现**：针对每个候选问题查明触发条件、违反的既有契约和影响。只报告真实路径上的高置信问题。先排除已有设计约定、无关旧问题和误读。
5. **验证**：优先已有 CI 证据和相关测试。需要运行命令时先核对代码、依赖与非破坏性范围；不执行不可信 PR 任意脚本来“看看结果”。不能安全运行就做静态审阅，写明限制。
6. **整理结论**：按重要性排序，区分必须处理、可选建议和既有问题。每条发现包含位置、触发条件、影响、证据与建议；建议不创造新的验收标准。
7. **核对版本**：结束时再次读取 head SHA。已变化则标明结论针对旧 SHA，不能冒充新版本审阅完成。
8. **回写**：仅写回来源卡片。失败也回写 phase:error，以便恢复按钮。没有发现阻断问题不代表保证无缺陷。

### 模板内的提交指令

> 审阅当前 PR 的指定 head SHA，结合本次批注。读取 PR 描述、实际 diff、相关上下文与仓库规范；核实问题的触发条件、影响和源码位置。只报告有证据的问题，区分必改项与建议。将结论、发现、验证和限制按 pr-review 协议写回来源卡片，不发布 GitHub review，不改代码、不推送、不合并。结束前核对 head SHA；失败也写回错误并复位请求。

发送参数使用点击时的 `{reviewId,prId,headSha,note}`，不是模板样例里的固定编号。长输入超过事件上限时明确提示，不静默截断。

## D. 增量与批注

- 每次结果记录 reviewedHeadSha。PR 更新后旧结论仍可作为历史参考，但要标过期。
- 重新审阅时可先看新旧 SHA 的差异，再针对被影响结论复核；不得把旧结论机械复制为新版本通过。
- 用户写“再看看这个边界”时，只重新检查点名部分及直接影响；写“修一下”才进入另外的本地修改流程。
- 用户要求发评论或正式 review 时，确认目标和内容后按当前远端写入政策执行；默认不做。

## E. 调研来源与取舍

以下为流程参考，不是额外质量门禁：

- [Google：审阅批注](https://google.github.io/eng-practices/review/reviewer/comments.html)：解释为什么，针对代码，区分 required / optional / nit。
- [Claude Code Review](https://code.claude.com/docs/en/code-review)：候选发现再核验、去重、严重度排序及具体代码位置。此处不照搬托管多代理规模或自动发布评论。
- [Addy Osmani review skill](https://github.com/addyosmani/agent-skills/blob/main/skills/code-review-and-quality/SKILL.md)：先理解意图和测试，避免因个人偏好阻断。此处不照搬固定行数阈值或未经授权修改代码做 mutation 试验。
