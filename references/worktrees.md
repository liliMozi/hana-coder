# 工作树与分支

## 初次调用

解析仓库根目录，用 prepare.py worktrees 生成完整目录卡片。脚本读取真实 Git 状态；Agent 只补解释，不编造事实。卡片绑定固定仓库，之后刷新不能被卡片状态里的另一个路径替换。

初始简介可用 `--summaries` 传 JSON 对象 `{完整工作树id:一句话用途}`。摘要证据不充分时注明推断；缺少摘要可先显示“简介待补充”。首次真实交付不得使用模板中的示例数据。

> 读取本事件来源卡片 state.model，确认 refreshId 匹配。采集已完成，不重复扫描。根据本轮 rows 为每个工作树写一句用途；必要时作最小只读核对。不要把继承自主线的提交当成当前分支用途。以完整工作树 id 为键，向来源 cardEntityId 回写 worktree-enrich 的成功结果；失败也回写对应错误，让按钮复位。不修改仓库，不推送，不删除工作树。

具体响应见 events.md。

## 事实含义

- “干净”只表示没有未提交文件，不代表任务完成或测试通过。
- 没有上游只表示未设置 tracking，不代表未推送。
- 领先/落后基于本地缓存远端引用；刷新不默认 fetch。
- 缺失目录、权限错误、detached HEAD、锁定或可清理标志按真实读取结果显示，不能静默跳过。
- 分支和目录不是同一实体；只按当前工作树列表展示时，不能声称已经列出所有未挂载分支。
- 合并状态不能只看提交标题；需要另行核对。常规刷新不授权自动清理。

## 独立实例

分页、简介、请求状态都属于当前卡片。固定视图、弹出视图可能各有独立实例，回写只对事件来源。丢失或过期 refreshId 不得覆盖新结果。Agent 运行失败或数据回写失败必须说明；卡片的显式重试入口用于用户重新发起，不在后台无限重试。
