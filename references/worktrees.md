# 工作树与分支

## 初次调用

解析仓库根目录，用 prepare.py worktrees 生成完整目录卡片。脚本读取真实 Git 状态；Agent 只补解释，不编造事实。卡片绑定固定仓库，之后刷新不能被卡片状态里的另一个路径替换。

初始简介可用 `--summaries` 传 JSON 对象 `{完整工作树id:一句话用途}`。摘要证据不充分时注明推断；缺少摘要可先显示“简介待补充”。首次真实交付不得使用模板中的示例数据。

## 刷新事件提示词

模板的 `hana-corder.enrich-worktrees` 事件内应包含下面的精简意图，并在点击时填入 repoPath 和 refreshId：

> 读取本事件来源卡片 state.model，确认 refreshId 匹配。采集已完成，不重复扫描。根据本轮 rows 为每个工作树写一句用途；必要时作最小只读核对。不要把继承自主线的提交当成当前分支用途。以完整工作树 id 为键，向来源 cardEntityId 回写 worktree-enrich 的成功结果；失败也回写对应错误，让按钮复位。不修改仓库，不推送，不删除工作树。

具体响应见 events.md。

## 创建与多选

选择和新建草稿属于当前卡片：`checkedIds`、`branchType`、`branchName`、`operation`。可选条目排除主工作树（`id` 等于 `repoPath` 或 `branch` 为 `main`），也排除读取失败、缺失目录、detached、locked、prunable。勾选只改变选择，不进入详情。跨分页保留选择；刷新后与新的可选集合求交。全选只覆盖当前全部可选工作树。

新建默认类型 `fix`，名称可留空。点击「＋ 新建」或「合并并清理」时，卡片先把请求写入 `operation` 并持久化，再分别 emit `hana-corder.create-worktree` 或 `hana-corder.merge-worktrees`。合并目标的 `{id,branch,head}` 留在 operation，不重复放入事件载荷。控件只在卡片就绪、宿主可保存状态并可 emit、没有进行中的刷新或操作、且已绑定仓库时可用。

Agent 只按当前卡片上明确提交、且 requestId 匹配的请求做本地操作。执行前自行核对仓库，不把卡片快照当最新事实。创建基于本地 main；合并只处理选定本地工作树，不扩大到远端推送或删除。响应协议见 events.md。宿主恢复时若 operation 未结束，保持等待，可停止等待，不自动重发。

## 事实含义

- “干净”只表示没有未提交文件，不代表任务完成或测试通过。
- 没有上游只表示未设置 tracking，不代表未推送。
- 领先/落后基于本地缓存远端引用；刷新不默认 fetch。
- 缺失目录、权限错误、detached HEAD、锁定或可清理标志按真实读取结果显示，不能静默跳过。
- 分支和目录不是同一实体；只按当前工作树列表展示时，不能声称已经列出所有未挂载分支。
- 合并状态不能只看提交标题；需要另行核对。常规刷新不授权自动清理。多选后的「合并并清理」才是一次明确的本地请求，仍然不授权远端写入。

## 独立实例

分页、简介、请求状态都属于当前卡片。固定视图、弹出视图可能各有独立实例，回写只对事件来源。丢失或过期 refreshId 不得覆盖新结果。Agent 运行失败或数据回写失败必须说明；卡片的显式重试入口用于用户重新发起，不在后台无限重试。
